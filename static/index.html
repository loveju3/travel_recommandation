0. 離線建置

商品「摘要文字」與「每日行程文字」各自產生 embedding（OpenAI text-embedding-3-small，1536 維）存進 Neon pgvector，並建 HNSW 索引；同時用 Jieba 斷詞建立 tsvector 全文索引（標題權重 A、標籤/特色 B、內文 C）。使用者偏好向量＝買過的商品（評分 × 時間衰減）＋收藏＋近期搜尋＋個人描述的加權平均。

▼

1. Query 理解

LLM 把自然語言拆成「結構化條件」（目的地、預算、天數、出發地、月份、類型、標籤）與「語意意圖」（改寫成完整描述給向量搜尋用）。可關閉，關閉時直接用原始 query。

▼

2. 過濾 + 雙路召回

結構化條件轉 SQL WHERE 硬過濾；在過濾後的集合裡同時跑 Jieba 關鍵字召回（擅長專有名詞，如「合掌村」）與 向量召回（擅長語意，如「帶爸媽」≈「長輩友善」）。結果太少時自動放寬條件。

▼

3. RRF 融合

Reciprocal Rank Fusion：score = Σ 1/(60+rank)。不需校準兩種分數的尺度，是業界常見的 hybrid search 作法。再加上 cosine 與標籤命中率得到「相關性分數」。

▼

4. 個人化重排

最終分數 = α·相關性 + β·個人化 + γ·商業因素。個人化＝使用者向量相似度 + 規則（預算、天數、出發機場、家庭組成、風格標籤）；商業＝熱門度、評分、名額急迫性、是否有可售團位。已買過的商品降權；新會員（冷啟動）自動把 β 分給相關性與商業。

▼

5. 可解釋性

每筆結果顯示分數拆解與命中原因；可選擇讓 LLM 依使用者輪廓寫一句推薦理由。所有搜尋寫入 search_logs，後續可接點擊資料做 Learning-to-Rank。
